**Subsystem scope:** Platform hardening (schema, provider reliability, first-party plan list API, OpenAPI snapshot, diagnostic observability)

## Summary

Ship milestone 1.1.0 as production-safe foundations for a single-instance learning app: Flyway-owned canonical schema with tests that migrate then `ddl-auto: validate`; explicit one-time adoption of a verified pre-Flyway 1.0.2 database; provider connect/read timeouts and conservative retry outside a database transaction; paginated plan summaries, a latest-plan read, and required `planDate`; a committed OpenAPI snapshot compared from the Testcontainers context; liveness/readiness, request-id correlation, and bounded provider/ranking metrics.

Out of scope: scheduling/clock times, user preferences, remaining-effort/actuals, task-list pagination, generate rate limiting, audit/`@Version`, Prometheus, structured JSON logging, external API compatibility windows.

This is one hardening milestone, not independent product subsystems. Slices below match the spec's five steps, with OpenAPI last so snapshot comparison sees the final HTTP surface (including `requestId` and health paths).

## Discovery notes

- Reuse: `PostgresIntegrationTest` Testcontainers + Windows npipe workaround; `DailyPlanAiTestConfiguration` for `@SpringBootTest`; `MockRestServiceServer` in `OpenAiDailyPlanClientTest`; existing `ConflictException` → 409; `apiRequest` already maps HTTP 204 to `undefined`; `generateDailyPlan` already injects the browser-local date (`{ planDate: getTodayDateString(), ...request }`); `PlanHistoryList` already only needs date, warning flag, and item count.
- Constraints: Java 21, Spring Boot 3.4, ArchUnit forbids `*Repository` depending on `..dto..` (projection lives in `com.focusflow.plan`, service maps to DTO). `spring.jpa.open-in-view: false`. Cookie session + CSRF unchanged. First-party API: frontend and backend ship atomically. Flyway `baseline-on-migrate` stays false on every normal profile.
- Patterns to follow: Owner-scoped reads, 404 for missing owned ids, 400 for validation, 502 for provider failures with nothing saved. Plan hooks invalidate `todayPlanQueryKey` and `plansQueryKey`. Extra JSON fields on errors stay nullable (`@JsonInclude(NON_NULL)`).
- Anti-goals: Do not auto-baseline unexpected databases. Do not retry read timeouts or HTTP 500. Do not infer "today" from `LocalDate.now()` at the API boundary. Do not paginate `GET /api/tasks`. Do not expose aggregate health details or Prometheus. Do not leave list queries with `@EntityGraph` after summaries land (issue 4 regression). Do not put OpenAPI snapshot generation inside ordinary tests.
