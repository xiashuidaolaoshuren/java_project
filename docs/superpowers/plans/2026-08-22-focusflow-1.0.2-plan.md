# Implementation Plan: FocusFlow 1.0.2

**Spec:** `docs/superpowers/specs/2026-08-22-focusflow-1.0.2-design.md`  
**Parent spec:** `docs/superpowers/specs/2026-05-14-focusflow-ai-design.md`  
**UI design spec:** `docs/superpowers/specs/2026-05-31-focusflow-frontend-ui-design.md`  
**Created:** 2026-08-22  
**Subsystem scope:** Daily plans (delete, plannable generation, ranking validation, persisted shortfall warning)

## Summary

Ship milestone 1.0.2 as one DailyPlan slice: owner-scoped hard delete of a saved plan (backend + history/detail UI); generation from plannable tasks (`OPEN` + `IN_PROGRESS`); ranking rules in the prompt with Java reject-not-repair of must-include blocks and leftover budget; persist `availableMinutes` and a shortfall warning snapshot on `DailyPlan` and render them after refresh.

Out of scope: remaining-minutes on Task, Flyway/Liquibase, soft-delete or replace-on-generate, backend-computed full ranking, calendar/preferences, task-delete changes, required estimates.

## Discovery Notes

- Reuse: `TaskService.deleteForCurrentUser` + `TaskController` `204`/`404` for plan delete. `TaskActions` confirm dialog for plan delete UI. `TaskQueryService` + `DailyPlanService.generate` + `DailyPlanPromptBuilder` for generation. `DailyPlanView` on dashboard and detail for the warning alert. Hibernate `ddl-auto` opt-in (`SPRING_JPA_HIBERNATE_DDL_AUTO=update`) for local schema; Testcontainers `create-drop`.
- Constraints: Java 21, Spring Boot, JPA/PostgreSQL, existing session CSRF, React/Vite/TanStack Query/shadcn. No new packages beyond `plan` / `ai` / `task` facades. ArchUnit: plan services must not touch `TaskRepository`.
- Patterns to follow: Owner-scoped `findByOwner_IdAndId` then 404. `AiProviderException` → 502, nothing saved. Frontend API in `features/plans/api.ts`, hooks invalidate `todayPlanQueryKey` and `plansQueryKey`. Extra JSON fields on list/get must stay backward compatible for old rows (`availableMinutes` and `warning` null).
- Anti-goals: Do not add Flyway. Do not make new columns `NOT NULL`. Do not repair AI order. Do not recompute warnings on read. Do not put delete on the dashboard. Do not leave `findOpenTasksByOwnerId` as the generate path.

## Workflow For Implementers

1. **writing-plans** produced this file (type-1 decomposition only).
2. For each subtask with **Plan mode: high** or **medium**, use Cursor **Plan mode** and the **planning-subtasks** skill to produce a type-2 plan (`.cursor/plans/*.plan.md`) before Agent mode when design risk warrants it.
3. In **Agent mode**, obey each subtask's **TDD suitable** tag with the **test-driven-development** skill: `yes` → strict red/green/refactor; `partial` → TDD only the named slice; `no` → satisfy **Verification** without forcing test-first.
4. Local schema: after P7, restart `bootRun` with `SPRING_JPA_HIBERNATE_DDL_AUTO=update` so Hibernate adds nullable columns. Do not use `create`/`create-drop` on the Docker volume you care about.
5. If implementation changes file paths, contracts, or task order, pause, update this plan, and add a **Plan changelog** row.
